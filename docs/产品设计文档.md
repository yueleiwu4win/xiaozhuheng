## 1. 产品概述

### 1.1 背景与目标

做一个**纯本地、离线、无账号**的个人记账 App，核心解决三件事：

1. **记得快**：3 秒内完成一笔支出记录（打开即记，不用等登录/联网）。
2. **看得清**：能按类别、按年、按月查看消费统计，并用图表直观呈现。
3. **拿得走**：所有数据可一键导出（CSV/JSON），不被 App 绑架，可自行备份分析。

### 1.2 设计原则

| 原则 | 说明 |
| --- | --- |
| 离线优先 | 不申请网络权限，数据只存在设备本地数据库 |
| 极简录入 | 首页直达记账，金额键盘 + 分类九宫格，最少点击完成 |
| 只做减法 | 不做多账本、不做共享、不做预算提醒（V1 不做，见范围） |
| 数据自主 | 分类、账单全量可导出；数据结构清晰可读 |
| 时间到天 | 记账时间粒度只到「日」，不需要具体时分秒选择 |

### 1.3 目标用户与典型场景

- 用户：单个自然人（本人），一台手机，长期持续记录。
- 场景 A：线下消费后立刻掏出手机记一笔（如午饭 25 元 → 餐饮）。
- 场景 B：旅行结束后集中补记（机票、住宿、打车、门票），需要快捷切换分类和日期。
- 场景 C：月底/年底打开统计页，看本月花了多少、今年哪一类花得最多。
- 场景 D：换手机或想做年度复盘，导出 CSV 到电脑用 Excel 分析。

### 1.4 范围

**In Scope（V1 必做）**

- 支出记账（收入作为可选开关，见 §16 待确认）
- 分类：预设分类 + 自定义新增/编辑/排序/删除（归档）
- 账单明细：按日期倒序列表、按月切换、按分类筛选、编辑、删除
- 本地存储（SQLite/Room），无网络
- 统计页：年度趋势折线图、某年 12 个月折线图、类别占比与排行、类别逐年对比
- 数据导出：CSV + JSON 全量导出，支持系统分享/保存到文件

**Out of Scope（V1 不做，列入后续版本）**

- 登录、注册、云同步、多端同步
- 多账本 / 多人共享记账
- 预算与超支提醒、周期性账单自动生成
- 多币种汇率换算（V1 单币种，字段预留）
- 账单拍照、小票 OCR、账单导入银行流水
- 桌面小组件、通知栏快捷记账（V1.2 考虑）
- 广告、任何形式的埋点上报

## 2. 术语定义

| 术语 | 定义 |
| --- | --- |
| 账单（Bill） | 一条消费/收入记录，包含金额、分类、日期、备注 |

## 4. 详细功能设计

### 4.1 记一笔（F-01 ~ F-04）

**入口**：底部导航「记一笔」/ 首页右下角悬浮按钮。

**页面元素（自上而下）**

1. 顶部：当前分类图标 + 分类名（点击可回到分类选择区）。
2. 金额显示区：大号数字，右侧显示币种符号（默认 ¥）。
3. 备注输入框（单行，选填，最长 50 字）。
4. 日期选择条：`今天 2025-06-14`（点击弹出日期选择器，可切换到历史日期；提供「今天/昨天」快捷键）。
5. 分类九宫格：一行 4~5 个，显示图标 + 名称；最后一个是「+ 添加」。可左右分页或纵向滚动。
6. 底部数字键盘：`7 8 9 ← / 4 5 6 + / 1 2 3 - / . 0 保存`；「保存」在金额 > 0 时高亮。
7. 校验：金额必须 > 0 且 ≤ 99,999,999.99，否则「保存」不可点。

**交互细节**

- 选择分类后页面不跳转，直接填充顶部并保持键盘可见（连续记账效率优先）。
- 保存成功后：Toast/Snackbar 提示「已记录 ¥25.00」，金额与备注清空，**分类和日期保持不变**（方便连续记同一天的多笔），光标回到数字键盘。
- 继续支持「再记一笔」的快捷流：保存后不退出页面。
- 若从明细页点某条账单进入，则是编辑模式，标题为「编辑」，提供「删除」按钮（二次确认）。
- 日期不允许选到未来（可配置允许，默认禁止）。

### 4.2 分类管理（F-05 ~ F-08）

**分类属性**：名称（≤6 字较佳，上限 10 字）、图标、颜色、排序序号、状态（启用/归档）、是否内置、类型（支出/收入）。

**内置分类（预设，不可删除，可改名/换图标/归档）**

- 支出：餐饮、交通、机票、住宿、购物、娱乐、医疗、教育、通讯、居家、人情、旅行其他、其他
- 收入（若开启收入）：工资、奖金、红包、退款、其他

> 说明：需求中明确提到「机票、饮食、住宿、交通」，因此内置分类包含这些；其余为常见补充项，用户可自行归档掉不用的。

**管理页能力**

| 操作 | 说明 |
| --- | --- |
| 新增 | 输入名称 → 选图标（内置约 60 个图标网格）→ 选颜色（预设 12 色）→ 保存 |
| 编辑 | 改名、换图标/颜色，立即生效，历史账单同步显示新名称（账单存 category_id 关联） |
| 排序 | 长按拖拽排序；排序结果决定记账区九宫格与筛选列表顺序 |
| 归档 | 归档后不出现在记账选择区与筛选列表，历史账单仍正常统计；可在「已归档」分组中恢复 |
| 删除 | 无任何账单引用时可硬删除；有引用时弹窗提示「该分类下有 N 笔账单，无法删除，是否改为归档？」 |
| 重名校验 | 同类型下分类名不可重复（提示「已存在同名分类」） |

**空态**：分类列表为空时（理论上不会，因有内置分类）显示引导。

### 4.3 账单明细（F-09 ~ F-11）

**列表结构**

- 顶部：月份选择器（`‹ 2025年6月 ›`）+ 本月合计（如「本月支出 ¥3,280.50 · 42 笔」）。
- 筛选条：分类 Chip 横滑；右侧「筛选」可展开日期范围/金额区间（P1）。
- 列表：按日分组，组头为 `6月14日 周六  ¥128.00`，组内按创建时间倒序显示 `图标 分类名  备注  ¥金额`。
- 空态：显示插画 + 「本月还没有记录，点这里记一笔」。
- 分页：按月加载（一个月数据量小，无需无限滚动优化），支持下拉刷新（实际是重新查询）。

**操作**

- 点击某条 → 进入编辑页。
- 左滑某条 → 显示「删除」（二次确认）；右滑 → 「复制一笔到今天」（P1）。
- 长按 → 多选批量删除（P1）。

### 4.4 统计页（F-12 ~ F-17）

统计页采用 **Tab 结构**，避免一屏塞太多图：

```
[ 总览 ]  [ 年 ]  [ 月 ]  [ 类别 ]      ← 顶部 Tab
[ 2025 ▾ ]                              ← 年份选择器（总览/年/类别共用）
```

#### Tab 1 · 总览（年度纵览）

- 指标卡 2×2：本年支出总额、月均支出、支出笔数、最高消费月。
- 图表 R1：**年度消费趋势折线图**（X = 年份，Y = 年度总支出），点击某年可跳转到「年」Tab。
- 图表 R3 精简版：本年各类别 Top5 横向条形图。

#### Tab 2 · 年（某年详情）

- 顶部年份切换器（默认当前年）。
- 图表 R2：**该年 12 个月消费折线图**（折线 + 数据点，缺数据的月份补 0；可切换柱状图）。
- 图表 R5：月度对比排行（12 个月横向条形，升/降序切换）。
- 同比信息：`2025 年 ¥38,400 · 较 2024 年 ↑12.3%`。

#### Tab 3 · 月（某月详情）

- 月份切换器（默认当前月）。
- 指标：本月总额、笔数、日均、最大单笔。
- 图表：本月各分类占比环形图 + 分类明细列表（金额、占比、笔数）。
- 与上月对比条：`较上月 ↓5.2%`。

#### Tab 4 · 类别（跨年对比）

- 选择某个类别（或「全部类别」）。
- 图表 R4：**各类别逐年消费对比多折线图**（X = 年份，每条线 = 一个类别，默认展示支出 Top5，可勾选增减）。
- 图表 R3：所选年份的类别占比饼图 + 完整排行表（类别、总额、占比、笔数、同比）。
- 排行表支持点击某类 → 展开该类的月度分布（P1）。

**通用交互**

- 图表与列表均支持「点击数据点 → 显示该点明细或下钻」。
- 无数据时：显示「暂无数据」占位，不显示空白坐标系。
- 所有统计均为**实时查询**（数据量级在万条以内，SQL 聚合 < 50ms）。

### 4.5 数据导出（F-18 ~ F-21）

**入口**：设置页 → 「导出数据」。

**导出流程**

1. 选择导出格式：CSV（表格分析） / JSON（完整备份）。
2. 选择范围：全部 / 指定年份 / 指定日期区间 / 指定分类（P1）。
3. 点击导出 → 调用系统文件选择器（SAF `ACTION_CREATE_DOCUMENT`），默认文件名：
   - `记账数据_20250614_1530.csv`
   - `记账备份_20250614_1530.json`
4. 也可选择「分享」→ 系统分享面板（微信/邮件/网盘），**分享动作由用户主动触发，App 自身不联网**。
5. 导出完成提示文件路径与条数。

**CSV 格式（UTF-8 带 BOM，逗号分隔）**

| 列名 | 示例 | 说明 |
| --- | --- | --- |
| 日期 | 2025-06-14 | ISO 格式 |
| 年 | 2025 | 便于数据透视 |
| 月 | 6 | |
| 类别 | 餐饮 | 导出时写入当时分类名 |
| 金额 | 25.00 | 两位小数，正数 |
| 类型 | 支出 | 支出/收入 |
| 币种 | CNY | |
| 备注 | 公司楼下快餐 | 含逗号/换行时按 CSV 规则加引号转义 |
| 记录时间 | 2025-06-14 20:11:03 | 创建时间戳 |

**JSON 格式**

```json
{
  "formatVersion": 1,
  "app": "bookkeeping-android",
  "exportedAt": "2025-06-14T20:11:03+08:00",
  "categories": [
    { "id": 3, "name": "机票", "type": "expense", "icon": "flight", "color": "#4A90D9", "sortOrder": 3, "archived": false }
  ],
  "bills": [
    { "id": 1024, "amount": 2580.00, "currency": "CNY", "type": "expense", "categoryId": 3, "categoryName": "机票", "date": "2025-06-01", "note": "北京-成都", "createdAt": "2025-06-01T09:12:00+08:00", "updatedAt": "2025-06-01T09:12:00+08:00" }
  ],
  "summary": { "billCount": 1, "totalExpense": 2580.00, "totalIncome": 0.00 }
}
```

**导入（P1）**：读取 JSON 备份 → 校验 formatVersion → 用户选择「合并（跳过重复）」或「覆盖（清空后写入）」→ 事务执行 → 结果报告（新增 N 条、跳过 M 条）。

## 6. 数据模型设计

### 6.1 表结构（Room / SQLite）

**category（分类表）**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK AUTOINCREMENT | |
| name | TEXT | NOT NULL | 分类名，同 type 下唯一 |
| type | TEXT | NOT NULL | expense / income |
| icon | TEXT | NOT NULL | 图标标识（内置图标名） |
| color | TEXT | NOT NULL | 十六进制色值，如 #4A90D9 |
| sort_order | INTEGER | NOT NULL | 升序排列 |
| is_preset | INTEGER | NOT NULL DEFAULT 0 | 1 = 内置分类 |
| is_archived | INTEGER | NOT NULL DEFAULT 0 | 1 = 已归档 |
| created_at | INTEGER | NOT NULL | 时间戳（毫秒） |

索引：`idx_category_type_sort (type, is_archived, sort_order)`

**bill（账单表）**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK AUTOINCREMENT | |
| amount_cents | INTEGER | NOT NULL | **金额以「分」存整数**，避免浮点误差 |
| type | TEXT | NOT NULL | expense / income |
| category_id | INTEGER | FK → category.id | 外键，删除策略 RESTRICT |
| date | TEXT | NOT NULL | `YYYY-MM-DD`（记账日期，精确到天） |
| year | INTEGER | NOT NULL | 冗余字段，= date 的年份，用于快速聚合 |
| month | INTEGER | NOT NULL | 冗余字段，1–12 |
| note | TEXT | NULL | 备注，≤50 字 |
| currency | TEXT | NOT NULL DEFAULT 'CNY' | 预留多币种 |
| created_at | INTEGER | NOT NULL | 创建时间戳 |
| updated_at | INTEGER | NOT NULL | 更新时间戳 |

索引：

- `idx_bill_date (date DESC)` —— 明细列表按日查询
- `idx_bill_year_month (year, month)` —— 月/年聚合
- `idx_bill_category_date (category_id, date)` —— 分类聚合与筛选

> 冗余 `year`/`month` 的原因：SQLite 中 `strftime('%Y', date)` 无法走索引，冗余列可让年度/月度聚合走覆盖索引，数据量到 10 万条仍能保持毫秒级。
> 时间戳统一存 UTC 毫秒，展示按设备时区转换；`date` 是纯日期字符串，不受时区影响（避免「跨时区记账跑到前一天」）。

设计取舍说明：

- **不做账本/用户表**：单用户单账本，避免无意义的关联与 UI 复杂度。
- **账单不冗余存分类名**：分类改名后历史账单同步更新（符合直觉）；导出时再快照分类名到 CSV。
- **金额存整数分**：所有汇总用整数相加，杜绝 0.1+0.2 类误差；展示层除 100 格式化。

## 7. 统计口径与算法

| 编号 | 指标 | 计算方式 | 备注 |
| --- | --- | --- | --- |
| M1 | 某年支出总额 | `SUM(amount_cents) WHERE type='expense' AND year=?` | |
| M2 | 某月支出总额 | `... AND year=? AND month=?` | |
| M3 | 月均支出 | 年度总额 ÷ 12 | 固定除 12，未记账月份按 0 计 |
| M4 | 类别占比 | 类别总额 ÷ 当期总额 × 100% | 保留 1 位小数 |
| M5 | 同比 | (本期 − 去年同期) ÷ 去年同期 | 去年为 0 → 显示「—」，不显示 ∞ |
| M6 | 环比 | (本月 − 上月) ÷ 上月 | 同上 |
| M7 | 日均（月） | 月总额 ÷ 当月已过天数（当月）/ 当月总天数（历史月） | |
| M8 | 最大单笔 | `MAX(amount_cents)` 及对应账单 | |
| M9 | 最高消费月 | 12 个月中 MAX 的月份 | 并列取最早月份 |
| M10 | 笔数 | `COUNT(*)` | 按筛选条件 |

**口径规则**

1. 统计只依据账单的 `date`（发生日期），与录入时间无关；补录的历史账单会正确归入历史月份。
2. 归档分类的历史账单**仍参与统计**（只是不能新记），否则历史报表会变化。
3. 折线图缺失月份**补 0**，保证 X 轴连续。
4. 收入（若开启）默认不计入「消费」统计，单独展示；V1 以支出为统计主体。
5. 所有金额展示统一两位小数 + 千分位（`¥3,280.50`）。

### 10.3 关键技术点

1. **金额**：全程 `Long`（分）运算，仅在展示层转 `BigDecimal` 格式化；数字键盘输入用字符串状态机解析（支持 `+`/`-` 中间运算）。
2. **聚合查询**：统计 SQL 直接 `GROUP BY year` / `GROUP BY year, month` / `GROUP BY category_id`，返回 `Flow<List<StatItem>>`，数据变化自动刷新 UI。
3. **导出实现**：`ContentResolver.openOutputStream(uri)` 流式写入，避免大结果集 OOM；CSV 首字节写 BOM（`EF BB BF`）确保 Excel 中文不乱码；备注字段按 RFC 4180 转义（含引号/逗号/换行时用双引号包裹并转义内部引号）。
4. **外键与事务**：`PRAGMA foreign_keys = ON`；分类删除走「有引用则拒绝」策略（RESTRICT）；导入采用单事务，失败整体回滚。
5. **数据库迁移**：Room `Migration` 显式声明，禁止 `fallbackToDestructiveMigration`，避免升级丢数据。
6. **无网络保证**：`AndroidManifest.xml` **不声明 `INTERNET` 权限**，从系统层面杜绝联网（这也是隐私卖点）。

### 10.4 图表自绘实现要点

- 基于 `Canvas` + `TextMeasurer`（Compose 原生，无第三方图表依赖）。
- 通用布局常量：左 48dp（Y 轴刻度）/ 右 12dp / 上 10dp / 下 26dp（X 轴标签）。
- **刻度取整**：最大值向上取到「好看」的刻度（1/2/2.5/5/10 × 10^n），保证 Y 轴为整值。
- **折线图**：支持多序列（R4 类别逐年对比）；单序列时带 10% 透明度面积填充；
  点击取「X 最近、Y 最近」的数据点下钻。
- **柱状图**：选中月份高亮 + 顶部显示完整金额，其余月份 55% 透明度。
- **环形图**：扇区间 1.5° 间隙，中心两行文字（总额 + 标签）；
  点击按「到圆环距离 + 极角」命中扇区。
- 缺数据补 0（应用层完成），X 轴标签点多时隔一显示（12 个月显示 1/3/5…月）。

## 附录 B · 示例统计 SQL

```sql
-- R1 年度消费趋势
SELECT year AS label, SUM(amount_cents) AS total
FROM bill WHERE type = 'expense'
GROUP BY year ORDER BY year;

-- R2 某年 12 个月（缺月补 0 在应用层处理）
SELECT month AS label, SUM(amount_cents) AS total
FROM bill WHERE type = 'expense' AND year = :year
GROUP BY month ORDER BY month;

-- R3 某年各类别总额
SELECT c.id, c.name, c.icon, c.color,
       SUM(b.amount_cents) AS total, COUNT(*) AS cnt
FROM bill b JOIN category c ON c.id = b.category_id
WHERE b.type = 'expense' AND b.year = :year
GROUP BY b.category_id ORDER BY total DESC;

-- R4 各类别逐年总额（Top5 类别在应用层筛选）
SELECT c.name, b.year, SUM(b.amount_cents) AS total
FROM bill b JOIN category c ON c.id = b.category_id
WHERE b.type = 'expense'
GROUP BY b.category_id, b.year ORDER BY c.name, b.year;
```

## 附录 C · 为什么不申请网络权限

1. 需求明确「不联网」，从 Manifest 层面移除 `INTERNET` 权限比在代码里自律更可靠——系统会直接阻止任何网络调用。
2. 无网络权限意味着不存在数据外泄通道，隐私说明可以写得非常硬。
3. 导出/分享动作通过系统 SAF 与 Intent 完成，由用户主动触发，App 自身不参与传输。
4. 代价：无法做云备份与崩溃上报——本项目为私人自用，可接受，用「定期导出 JSON 备份」替代。
