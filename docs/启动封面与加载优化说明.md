# 启动图标与加载优化

## 实现

- 使用用户最新提供的方形图片“汉服女子静心拨珠算盘.png”作为桌面、安装和启动图标。等比例缩放为位图图标，增加透明安全边距；资源为 `app/src/main/res/drawable-nodpi/brand_icon_foreground.png`。
- 图标与启动窗口使用暖白 `#F7F5EF` 背景，正式页面一次应用已保存的主题。
- Android 12 及以上直接使用系统图标启动页，较早版本使用同图标的窗口背景；删除应用内全屏启动封面及旧大图资源，避免先小图标再大图。
- 用 OnPreDrawListener 保持一个启动窗口，必要数据准备好且首页组合完成后才放行第一帧；冷启动从 Activity 创建起至少保留 600ms 图标阶段，状态恢复不重复等待，后台热恢复不会重新播放。
- 系统启动阶段本身由 Android 管理，启动器的动画、图标形状和具体手机效果仍需设备验证。
- 启动只准备设置、分类和当月账单。首次安装默认分类写入使用数据库事务，完成后再发布缓存，避免短暂的空分类。
- 备份、导出、背景图片存储的功能对象按需创建，年度统计仍在进入统计后加载。
- 设置与上次分类由一个应用级订阅维护，页面复用 StateFlow，避免每次先显示默认设置再读取真实设置。
- 分类由一个应用级 Room 订阅维护。修改、归档、恢复、排序及导入触发缓存刷新；区分“尚未加载”和“已加载但为空”。
- 新记账直接使用当前分类快照和上次分类，首帧已有完整分类与选中项；切换收支也从缓存选择，不重新查询。
- 编辑已有账单时，等记录读取完成再显示完整表单；管理分类后同步名称及可用状态，历史账单仍可保留归档分类。
- 当月账单缓存持续跟随数据库更新，首页列表和概览的初始值来自同一份已读取的数据，避免先显示零额再刷新。
- 数据准备失败显示重试入口；在 Logcat 的 `Startup` 标签记录必要数据准备耗时与 Activity 到首页绘制的耗时，并调用 `reportFullyDrawn()`。

## 安装包与验证

`preview` 使用非调试运行模式，不包含调试专用 UI tooling，沿用本地调试签名，可覆盖现有 Debug 安装；正式发布的签名配置没有更改。

当前品牌名称为“小珠衡”，桌面、安装界面、首页共用 `app_name` 资源；图标为用户提供的汉服女子算盘图片。版本显示仍为 1.0，升级序号 versionCode 为 3。

交付构建任务：`.\gradlew.bat :app:packageXiaozhuheng`，文件为 `app/build/outputs/distribution/xiaozhuheng-v1.0.apk`。

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assemblePreview
```

新测试覆盖默认分类回退、归档分类排除、收支切换、空分类，以及分类缓存被修改/归档/备份替换后的更新。已有金额、账单合计、备份校验等测试一并回归。

尚无连接设备，无法提供实测冷启动耗时或确认特定手机上的绘制帧率。设备验收建议：

1. 首次安装与已有账单各冷启动一次，只出现一张小图片启动图标，随后直接进入首页，不再出现全屏插画。
2. 系统深色/应用浅色、系统浅色/应用深色分别冷启动，正式页面不先显示错误主题。
3. 连续进入新记账、切换收入/支出，分类与默认选中项同步出现。
4. 记账页进入管理，改名/排序/归档后返回，分类更新且可正常保存。
5. 恢复备份后检查首页和记账分类；切换后台再回来不重复展示封面。
6. 在同一手机分别用 Debug 与 Preview 测冷启动和热恢复，结合 `Startup` 日志和 `adb shell am start -W` 比较，不能将后台准备耗时等同于系统总启动耗时。

实现参考：[Android 启动页](https://developer.android.com/develop/ui/views/launch/splash-screen)、[应用启动时间](https://developer.android.com/topic/performance/issues/launch-time)。
