# 1.2.0：月度预算、快捷记账、月度小结

开发分支：`codex/monthly-tools`。全部数据与小结在本机处理，无网络权限。

## 使用

- 首页概览下方点击预算条，或设置 → 记账 → 月度预算。预算按月份独立保存，可沿用上月、修改或取消。仅累计支出，收入不抵扣，筛选不影响金额；超过预算仍可记账。补记、删除、修改自动更新。
- 长按桌面图标，选择「记支出」或「记收入」。日期默认今天，分类采用对应类型上次有效分类。快捷入口不强制停留 600 毫秒，必要数据就绪就进入记账。入口由手机启动器提供，是否支持拖到桌面取决于启动器。
- 统计 → 月度分析 → 查看月度小结。包含收支、结余、上期比较、前三支出分类、最大单笔、预算结果和本地模板总结。
- 小结可隐藏金额，生成图片后先查看完整预览，再保存或主动调用系统分享。预览与输出使用同一张位图，默认清晰底色，可选择淡人物背景。不会分享备注；不会自动发送给联系人。

## 口径

当前月份截至今日，对比上月同日（短月份截到月末）；历史月份对比完整上月。页面和海报明确显示日期范围。上期为零时只说明金额，不计算增长率。收入存在而支出为零、无账单均有独立文案。分类、最大单笔按相同日期范围查询，金额继续以整数分运算。

预算输入必须大于零，最多八位整数、两位小数；预算按 `yyyy-MM` 存储。首页进度上限为 100%，文字保留真实使用比例与超支金额。

## 代码与数据

- `BudgetDao` / `BudgetRepository` 管理新表 `monthly_budget(month PRIMARY KEY, amountCents, updatedAt)`；首页通过 Flow 观察所选月份预算。
- Room 从 1 升级到 2，`MIGRATION_1_2` 只新增预算表，不重建账单或分类表，不允许破坏性迁移。已导出版本 1 和 2 的 schema。
- JSON 备份为格式 3，预算、分类、账单在同一读取事务导出。恢复时三类数据在同一写事务替换；预算格式错误时整份文件拒绝恢复。旧格式 1/2 兼容，预览明确说明旧备份不含预算、恢复将清空当前预算。清空全部数据也清空预算。CSV 保持账单格式。
- `MonthlySummaryRepository` 观察账单、分类、预算的失效通知，按需用 SQL 聚合，在一个读取事务中产生完整小结；分类重命名或备注修改等总额不变的操作也可刷新。
- `SummaryPeriod`、`MonthlySummary` 提供可测试的日期与总结规则；`SummaryPoster` 使用 Android Canvas 与 StaticLayout 完整绘制，自动换行，不依赖截屏或滚动位置。
- 静态快捷方式指向空任务归属的 `QuickEntryActivity`，再以 NEW_TASK/CLEAR_TOP/SINGLE_TOP 转到 MainActivity，避免系统静态快捷方式默认 CLEAR_TASK 销毁现有草稿。无修改时直接进入，有修改先确认；正在保存/删除时忽略新入口请求，避免重复操作。

## 验证

- `:app:testDebugUnitTest`：预算金额边界、月份日期比较、零基数、隐藏金额、格式 3 预算解析与旧备份兼容，以及既有功能回归。
- `python tools/check-budget-migration.py`：宿主 SQLite 使用生产迁移 SQL 与导出的 Room schema，验证旧数据保留、新表结构、月份独立、外键及事务回滚。
- `:app:assembleDebugAndroidTest`：编译原生 Room 迁移与备份原子性测试。连接设备后运行：

```text
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w com.example.bookkeeping.test/com.example.bookkeeping.MigrationInstrumentation
```

该测试使用独立临时数据库，不读写正式账本。设备不存在时只能编译，不能声称已完成设备测试。

- `MonthlyToolsSnapshotTest`：四主题 × 普通/150% 字号，渲染真实预算条与小结组件，示例数据，不代表真机操作或帧率测试。
- 最终交付前执行 lint、原生截图验证、preview 打包、APK 元数据与签名校验。桌面长按、冷/热启动、输入中再次快捷启动、文件选择与分享需要真机补验。
